## Findings

1. **Material — two documents describe the round-2 safety net as failing on the wrong side, and the wrong side is the one that invites the destructive fix.** `.github/workflows/visual-baselines.yml:15-16` says "a story the manifest lost by accident fails the confirm step as a **missing** picture instead of losing it", and `tools/src/visual/baselines.mjs:8-10` repeats it ("must fail the run as a missing picture, not lose it"). It fails as an *orphan*. A story that drops out of `dist/ladle/meta.json` leaves `expected()` (`baselines.mjs:57-60`), so its committed PNG has nothing naming it; I reproduced this against a copy of the module in `/tmp` by removing one key from a stand-in `meta.json`, and the script printed `orphan baseline, no story or view is named for it: stories/a--one` (plus the `stories-dark` twin) and exited 1 — never the word "missing". The mechanism is right; the prose points the operator at the wrong lever. Someone who read those two comments, then hits red CI reading "orphan baseline", will reasonably conclude they are in the deliberate-deletion case the header reserves `-f prune=true` for, dispatch with prune on, and delete the picture of a story that still exists — which is precisely the loss A2-2 was raised to prevent. `AGENTS.md:118-119` gets it right ("fails the run rather than losing its picture"); the two files nearest the failure do not.

2. **Minor — the dispatch recipe cannot be copy-pasted.** `.github/workflows/visual-baselines.yml:8-9` renders the prune flag as a second line under the command with no continuation backslash:
   ```
   gh workflow run visual-baselines --ref <that branch>
     -f prune=true         # only after deleting or renaming a story: removes its pictures
   ```
   Pasted as written, line 8 dispatches *without* prune and line 9 fails as `command not found: -f`, leaving the operator with a run that did the wrong thing and an error that does not explain why. The rest of that block is a working copy-paste recipe, which is what makes the break easy to miss.

3. **Minor — `onDisk` walks every directory but still only sees one filename shape, so three classes of stray file remain invisible.** `tools/src/visual/baselines.mjs:78-80` filters on `endsWith('-linux.png')` after the new directory scan. Exercised against the `/tmp` copy: a PNG without the platform suffix in an expected directory (`baselines/studio/cockpit-light.png`), an unexpected directory containing no PNGs (`baselines/zzz/`), and a `-darwin.png`-only directory each produced `baselines match the stories and views`, exit 0. The workflow's `git add -A tools/src/visual/baselines` (`visual-baselines.yml:79`) will happily commit any of them. The realistic path in is someone running `CI=1 pnpm visual --update-snapshots` on the Mac, which writes `-darwin` files that no check will ever report or prune — `difference()` is parameterised by platform but every caller uses the default (`manifest.visual.mts:16`, `baselines.mjs:106`) and the prune path hardcodes `-linux.png` at `baselines.mjs:109`. Low likelihood, permanent once it happens.

4. **Minor — `SCHEMES as Scheme[]` is an unchecked assertion that undoes the type safety its row claims.** `tools/src/visual/studio.visual.mts:28` casts the import from `baselines.mjs:23`, which is plain JS under `allowJs: true, checkJs: false` (`tools/tsconfig.lib.json`), so TypeScript infers `string[]` and the cast is legal but tells it nothing. A2-3's row says views "cannot part from" their behaviour; the `menu` flag genuinely delivers that, but the scheme list does not — add a third scheme and `studioNames()` (`baselines.mjs:35-39`) grows the expected set while `page.emulateMedia({ colorScheme })` at `studio.visual.mts:17` receives a value Playwright rejects. It fails loudly rather than photographing the wrong thing, so this is a durability point, not a hole: `export const SCHEMES = /** @type {const} */ (['light', 'dark'])` in the `.mjs` would make the cast unnecessary and the mistake compile-time.

5. **Minor — the diff redefines "view" without updating the two places that count them.** `STUDIO_VIEWS` now holds two entries (`baselines.mjs:29-32`), each one view photographed in both schemes, while `AGENTS.md:113` and `tools/src/visual/playwright.config.mts:2` both still say "four studio views". Four baselines, two views. Nobody is misled about what CI does, but a reader who greps `STUDIO_VIEWS` after reading AGENTS.md finds half the number they were told to expect.

**`if: ${{ inputs.prune }}` behaves in both directions.** GitHub documents the distinction the fix depends on: "The information in the `inputs` context and `github.event.inputs` context is identical except that the `inputs` context preserves Boolean values as Booleans instead of converting them to strings" ([Events that trigger workflows](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows), [Contexts reference](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts)). So the omitted-input case evaluates the `default: false` as a real boolean and skips — the classic `github.event.inputs.prune` trap, where the string `"false"` is truthy and prune runs every time, is not what was written.
